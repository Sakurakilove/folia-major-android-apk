# Android 功耗治理与原生替换

## mobile.17 的依据与改动

用户反馈：骁龙 8 Gen 2、未充电、莫奈，且其他页面也接近 10W。这是实机反馈；当前工作环境没有该设备的 CPU/GPU trace。APK 编译通过不能作为节电证据。

本批实际改动：

- 玻璃发现与动画观察分离。全局只发现结构/类名变化；高频 style 只观察玻璃表面及祖先，不为逐字遮罩、阴影、进度条生成属性记录。
- Java 按真实像素预计算光学外包围、半尺寸、折射高度和梯度半径；AGSL 在无效区域直接返回原像素。折射/七色采样/深度法线/高光公式和分辨率不变。
- 莫奈每行一个时钟订阅替代每词多条 MotionValue 派生；词只在时间窗口内计算，重复值不写 DOM，扫字完成后保持同一遮罩和渐变。glow 仍按原半径/颜色/绝对时间绘制，没有删掉。
- 原浮动装饰的五个关键帧、时长、延迟、逐段 easeInOut 与无限循环交给 Web Animations 原生合成器；不再由 JS 每帧写四类属性。
- 72 个频谱采样窗口/权重按 FFT 长度缓存；线点池复用，时间/anchors 每帧只求一次。不降低频谱精度、数量、DPR 或帧率。
- 新 `FoliaPowerSnapshot.java` 按需读取进程 CPU/电池计数，不创建计时器、监听器或唤醒锁。JS 在可见页面稳定后只取相隔 8 秒的两次快照，40 秒内不重复已完成采样，切页/隐藏取消过期结果。现有日志中的 `[AndroidPower]` 明确标注计数口径。

## 原生重写的边界与顺序

“换成 Kotlin/Java”本身不会减少相同像素的 shader 运算。Chromium 的音频解码、GPU 合成已使用 Android 原生实现；额外叠一个原生层也可能增加合成开销。当前未把整个产品重写成原生。

1. **渲染场景与玻璃**：当前 RenderEffect 仍需整 WebView 离屏输入。本批减少其运算，未移除该缓冲。真正局部化需要单一原生场景输出背景、歌词/墙和玻璃，或能直接共享已有 GPU 图像的模块；禁止再次录制同一 WebView、截图、PixelCopy 代替实时场景。现有 DOM/mod CSS、主题、字体、命中测试、手势、翻牌和无闪帧交接均属于替换验收契约。
2. **莫奈文字**：本批合并了调度，动态 textShadow 仍会重栅格化。候选为原生 Skia/RenderNode 或 GPU glyph/glow atlas，由原始字体和实际测量提供缓存，绝对时钟/扫光/副歌强度不变。未验证字体/blur 精确性前不能直接替换成近似 TextView 或静态 glow。
3. **播放**：原生 Media3 是候选，但需等价提供所有在线鉴权、URI/Range、双 deck 混音、完整音效、倍速、淡变与 PCM/FFT 时钟。现有音频经用户确认已正常，不能为原生化先删除音效或改用另一个不等价输出。
4. **设置/壳与业务**：Java 已承载原生文件、窗口、权限、密钥和媒体会话等。设置/底栏可逐模块替换，但需处理其在玻璃、模态窗和 mod 图层中的正确遮挡；不能让一个原生浮层永远压住所有网页弹窗。Node 平台业务后端仍在，未声称已移除所有 JS。

## 计数口径

电池 current-now × voltage 是**整机瞬时估算**，可能有厂商采样延迟/单位实现差异，充电时不生成放电瓦数。宿主 CPU 增量 / 时间差是 CPU 核心等价占用，不包括隔离的 Chromium renderer/GPU 或其他应用；不能据此宣称应用单独耗电多少瓦。

必要宿主验证只检查算法/构建，不替代手机画面、交互与功耗。需要由同一设备、亮度、刷新设置、曲目/动画场景对比 mobile.16/17，最终瓦数以实机为准。没有为测试而加常驻 FPS 或高频日志。

可复现的最小词样式对照：`node test/manual/android/checkMonetWordPaint.cjs <mobile.16 的 MonetRailTokens.tsx 路径>`。使用真实旧/新组件与共享公式，固定字素测量偏移，不检查字体栅格或浏览器视觉。
